QuasarBot Privacy Policy

Last updated: November 16, 2026

This policy explains what data QuasarBot ("the bot") collects, why, how long it is kept, and what choices you have. By adding or using the bot, you agree to this policy. If you do not agree, please do not use the bot.

Questions? Join the support server: https://discord.gg/kXwAQRNq2d

1. What QuasarBot is

QuasarBot is a Discord bot for partnership servers. It tracks partnership ads, manages a Rep Role, protects servers from hit-and-run joins and bot accounts, and offers welcome messages, auto responders and auto reactions.

2. Data the bot stores

The bot stores only what it needs to work. Here is the full list.

Server settings (when a server admin runs setup):

  • Server ID
  • IDs of the ad channel, Rep Role, log channel, trap channel and Rep-Warning Category
  • Your chosen options (J2L on or off, trap action, rep leave action, timezone)

Partnership tracking:

  • Server ID, user ID of the partner who was mentioned in an ad, and the ID of the ad message and its channel

Features you set up:

  • Auto responders: the trigger words, the replies, and the channel and staff-only options
  • Auto reactions: the channel and the emojis
  • Welcome messages: the welcome channel, the message text and the DM option

Bot status data:

  • When the last daily scan ran for a server
  • A per-user switch for members who choose to stop getting Ad Category notices (server ID and user ID)

Polls from the developer:

  • If you vote in a poll the developer sends to servers, your user ID and your choice are stored so each person counts once.

3. Data the bot reads but does not store

To do its job, the bot reads messages in the channels it manages (the ad channel, the Ad Category, the trap channel, and channels with auto responders or auto reactions). It checks them in memory, for example to see whether an ad mentions a partner or whether a message contains a trigger word. The bot does not save the text of your messages. It saves only the message ID and channel ID of tracked ads.

The bot also uses your join time and role information to decide whether join-and-leave protection or the Rep Role rules apply. This is used at that moment and is not kept.

4. Where data appears outside the database

  • Server logs. The bot posts log messages (for example "Partnership Logged" or "Trap Triggered") in the log channel the server admin chose. These can include user mentions, user IDs and links to messages. Server admins control who can see that channel.
  • Direct messages. The bot may send a DM when you are removed by the trap channel, when the welcome DM option is on, and to a server owner when the bot is added.
  • Support tickets. If you use /report, a private ticket channel is created in the QuasarBot support server. When the ticket is closed, a text transcript (up to 2,000 messages) is sent to a private developer channel. Do not share secrets in tickets.
  • Error reports. When something goes wrong, the bot sends a technical error report to a private developer channel. It can include the server ID, channel ID, your user ID, the command used and a technical trace. It does not include message content.
  • Backups. Copies of the database are made regularly and stored in a private developer channel, so data can be restored after a failure. A backup contains the data listed in section 2.

5. Why the data is used

  • To run the features you or your server admins turned on
  • To keep the bot working and fix bugs
  • To protect servers from abuse
  • To answer support requests

The bot does not sell your data, show ads, or use it for profiling. It does not share data with anyone except as described in section 7.

6. How long data is kept

  • Removing the bot. When the bot is removed or kicked from a server, it deletes that server's settings, tracked ads, responders, reactions, welcome message and status data.
  • Ads and members. A tracked ad record is deleted when the ad is deleted. Records for a member are deleted when that member leaves the server.
  • Reset. A server admin can use /setup and its reset option to delete the server's data at any time. /remove-welcome deletes the welcome settings.
  • Poll votes are kept until the poll data is removed.
  • Backups, error reports and ticket transcripts are kept for a limited time in private developer channels and are not deleted automatically. They can be deleted on request (see section 9). Data in an old backup is not changed by later deletions, but it is removed when that backup is deleted.

7. Who data is shared with

  • Discord. The bot runs on Discord, so Discord handles all messages and servers under its own privacy policy.
  • Hosting and database providers. The bot and its database run on third-party hosting services. They store data only to run the service for the developer.
  • No one else. Data is not sold or rented. It is only shared if the law requires it, or to protect the safety of users or the bot.

8. Security

The bot uses reasonable steps to protect data, such as limiting access to the database and private channels. No system is completely secure, and the developer cannot promise perfect security.

9. Your choices and rights

  • Server admins can change or delete their server's data with /setup, /remove-welcome, /autoresponder, /autoreact, or by removing the bot.
  • Members can ask what the bot has stored about them, or ask for it to be deleted, by contacting the support server. Please include your user ID. The developer will reply and act as soon as reasonably possible.
  • Poll votes and backups are handled by request.

Depending on where you live, you may have more rights under local law, such as the right to access, correct or delete your data. Contact the support server to use them.

10. Children

Discord requires users to be at least 13 years old (or older where local law says so). The bot is not meant for anyone under that age and does not knowingly collect their data. If you think a child's data is stored, contact the support server and it will be deleted.

11. Changes to this policy

This policy may change as the bot changes. The date at the top shows the latest version. If a change is important, the developer will announce it in the support server or through the bot. Continuing to use the bot after a change means you accept it.
